# 00 · 导读：让 Blender 听你指挥

## 为什么写脚本

入门版里，你建一栋房子要做这些事：添加立方体 → 缩放 → 移动 → 复制 → 改名字 → 改材质 → 复制材质……

30 栋房子就是 30 × 8 = 240 次手动操作。改一次窗格尺寸，要重做 240 次。

写成脚本：

```python
for i in range(30):
    build_house(i)
```

改一次窗格尺寸，跑一次脚本，30 栋全部更新。**这就是程序化的价值。**

Blender 内置完整的 Python 运行环境，你的脚本可以：

- 创建/修改/删除任何物体、材质、灯光、相机
- 直接编辑网格顶点
- 搭建节点材质
- 设置关键帧与动画曲线
- 调用渲染、导出、保存
- 读取外部文件生成内容

## 环境的三个概念

### 1. 数据块（Data Block）

Blender 的所有内容——网格、材质、物体、灯光——都存在**数据块**里，物体只是指向数据的"指针"。

```
数据块：Mesh "CubeMesh"（真正的顶点数据）
   ↑ 引用
物体：Object "Cube"（位置/旋转/缩放/名字）
```

这解释了一个常见现象：复制一个物体（`Ctrl + D`）后移动它，原始物体不动——因为复制的是**物体**，网格数据还是共享的。要独立就得"使数据独立"。

### 2. 集合（Collection）

物体按集合组织，类似文件夹。渲染、隐藏、导出都能按集合批量操作。

### 3. 上下文（Context）

脚本操作需要知道"在哪个区域、对哪个物体操作"。`bpy.context` 提供当前环境。脚本里最常用的是：

```python
bpy.context.view_layer.objects.active   # 当前活动物体
bpy.context.scene                       # 当前场景
```

## 第一个脚本

新建 `hello.py`：

```python
import bpy

# 清空默认场景
bpy.ops.object.select_all(action="SELECT")
bpy.ops.object.delete()

# 创建一个立方体
bpy.ops.mesh.primitive_cube_add(size=2, location=(0, 0, 1))

# 拿引用
cube = bpy.context.active_object
cube.name = "MyCube"

# 加材质
mat = bpy.data.materials.new("M_Orange")
mat.use_nodes = True
bsdf = mat.node_tree.nodes["Principled BSDF"]
bsdf.inputs["Base Color"].default_value = (0.9, 0.38, 0.06, 1.0)
cube.data.materials.append(mat)

# 加一盏灯
bpy.ops.object.light_add(type="SUN", location=(4, -4, 8))
sun = bpy.context.active_object
sun.data.energy = 3.0
sun.rotation_euler = (0.6, 0, 0.8)

# 加相机
bpy.ops.object.camera_add(location=(6, -6, 4))
cam = bpy.context.active_object
cam.rotation_euler = (1.0, 0, 0.78)
bpy.context.scene.camera = cam

# 渲染
bpy.context.scene.render.engine = "BLENDER_EEVEE"
bpy.context.scene.render.filepath = "/tmp/hello.png"
bpy.ops.render.render(write_still=True)
print("DONE")
```

运行：

```bash
blender -b --factory-startup --python hello.py
```

**验证**：打开 `/tmp/hello.png`，应该是一个橙色立方体在灰色背景上，有明确的光影。

## 命令行参数：让脚本可配置

教程里的脚本都做成"传参可配置"，这是工程化的基本要求。

```python
import bpy, sys, os

# 解析命令行参数
argv = sys.argv
out_dir = argv[argv.index("--") + 1]      # 必须用 -- 之后的部分
os.makedirs(out_dir, exist_ok=True)

# 运行
bpy.context.scene.render.filepath = os.path.join(out_dir, "hero.png")
bpy.ops.render.render(write_still=True)
```

运行：

```bash
blender -b --factory-startup --python hello.py -- ./out
```

> 💡 `sys.argv` 里 Blender 自己会塞一堆参数，所以要用 `argv.index("--")` 找到分隔符后面才是你自己的参数。

## 常用 API 速查

| 想做的事 | API |
|---------|------|
| 新建物体 | `bpy.ops.mesh.primitive_cube_add()` |
| 新建空物体 | `bpy.data.objects.new(name, None)` |
| 链接到场景 | `scene.collection.objects.link(obj)` |
| 删除物体 | `bpy.data.objects.remove(obj, do_unlink=True)` |
| 新建材质 | `bpy.data.materials.new(name)` |
| 新建灯光 | `bpy.data.lights.new(name, type)` |
| 访问网格顶点 | `mesh.vertices` / `mesh.from_pydata()` |
| 设置父级 | `child.parent = parent_obj` |
| 关键帧 | `obj.keyframe_insert("location", frame=1)` |
| 场景渲染设置 | `bpy.context.scene.render.*` |
| 合成器节点组 | `bpy.data.node_groups.new(name, "CompositorNodeTree")` |

## 本章要点回顾

- Blender 内置完整 Python，能自动化一切操作
- **数据块 vs 物体**：数据是本体，物体是引用
- 集合用于组织，context 提供当前操作环境
- 脚本要用 `--` 传参，用 `sys.argv` 读取
- `bpy.ops.*` 是操作符（依赖上下文），`bpy.data.*` 是数据访问（不依赖）
