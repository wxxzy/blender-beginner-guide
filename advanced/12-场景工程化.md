# 12 · 场景工程化

## 概念

场景做到几百个物体后，问题从"能不能做出来"变成"**能不能维护、能交付、能重复产出**"。

三个核心手段：**集合组织** → **数据复用** → **命令行渲染**。

## 集合：场景的文件夹

```python
def new_collection(name, parent=None):
    coll = bpy.data.collections.new(name)
    (parent or bpy.context.scene.collection).children.link(coll)
    return coll

def link(obj, coll):
    """把物体移到指定集合（先从旧集合解绑）。"""
    for c in list(obj.users_collection):
        c.objects.unlink(obj)
    coll.objects.link(obj)
    return obj
```

## 数据复用：链接 vs 复制

这是 Blender 里最重要也最容易误解的概念。

```python
# 复制物体：新物体 + 新数据（完全独立）
obj2 = obj.copy()
obj2.data = obj.data.copy()      # ← 这一行决定了是否独立

# 链接物体：新物体 + 共享数据
obj2 = obj.copy()                # 不动 data → 共享网格
```

### 实例 vs 真实物体

| | 真实物体 | 实例（空物体 + 实例类型） |
|---|---|---|
| 网格数据 | 独立 | 共享 |
| 30 个的内存 | 30 份 | 1 份 |
| 改一个 | 只影响它 | 影响全部实例 |
| 适合 | 需要单独改的 | 大量重复的（窗格、栏杆、瓦片） |

**实例的创建**：

```python
def make_instances(source, count, positions, coll):
    """创建 count 个实例，共享同一份网格数据。"""
    objs = []
    for i, pos in enumerate(positions):
        ob = bpy.data.objects.new(f"{source.name}_Inst_{i:03d}", source.data)
        ob.location = pos
        coll.objects.link(ob)
        objs.append(ob)
    return objs
```

**这就是"30 栋房子只占 1 份数据"的实现方式**——但要注意，改网格数据会同时改掉所有实例。

### 集合实例（Collection Instance）

比单物体实例更强，可以实例化一整个集合：

```python
def instance_collection(source_coll, name, loc, rot=(0,0,0), scale=(1,1,1)):
    """把整个集合实例化成一个空物体。"""
    emp = bpy.data.objects.new(name, None)
    emp.instance_type = "COLLECTION"
    emp.instance_collection = source_coll
    emp.location = loc
    emp.rotation_euler = rot
    emp.scale = scale
    bpy.context.scene.collection.objects.link(emp)
    return emp
```

**用法**：先手工做好"一栋房子"的完整集合（墙、窗、门、屋顶），然后用集合实例复制 30 份。改原型 → 全部更新。

## 命令行渲染

### 统一的入口脚本

```python
# render.py
import bpy, sys, os, argparse

def get_args():
    argv = sys.argv
    if "--" not in argv:
        return argparse.Namespace(out=".", mode="still", frame=1,
                                 res="1920x1080", samples=64, count=1)
    p = argparse.ArgumentParser()
    p.add_argument("--out", required=True)
    p.add_argument("--mode", default="still")
    p.add_argument("--frame", type=int, default=1)
    p.add_argument("--res", default="1920x1080")
    p.add_argument("--samples", type=int, default=64)
    p.add_argument("--count", type=int, default=1)
    return p.parse_args(argv[argv.index("--") + 1:])


def main():
    args = get_args()
    os.makedirs(args.out, exist_ok=True)
    sc = bpy.context.scene
    w, h = (int(x) for x in args.res.lower().split("x"))
    sc.render.resolution_x, sc.render.resolution_y = w, h
    sc.render.resolution_percentage = 100
    sc.render.image_settings.file_format = "PNG"

    if args.mode == "hero":
        sc.render.filepath = os.path.join(args.out, "hero.png")
        bpy.ops.render.render(write_still=True)

    elif args.mode == "frames":
        sc.render.filepath = os.path.join(args.out, "frame_")
        bpy.ops.render.render(animation=True)

    elif args.mode == "preview":
        for f in (1, 120, 240):
            sc.frame_set(f)
            sc.render.filepath = os.path.join(args.out, f"preview_{f:04d}.png")
            bpy.ops.render.render(write_still=True)

    print("RENDER DONE")

main()
```

调用：

```bash
# 主图
blender -b scene.blend -P render.py -- --out ./out --mode hero --frame 165 --res 2400x1350 --samples 96

# 序列
blender -b scene.blend -P render.py -- --out ./out --mode frames --count 32 --res 1600x900 --samples 64
```

### 渲染中断续渲

序列渲染时如果中断，重跑会从头开始。用 `use_overwrite` + 判断文件是否存在跳过：

```python
def render_frames_skip_existing(sc, out_dir, frames, res, samples):
    w, h = res
    sc.render.resolution_x, sc.render.resolution_y = w, h
    sc.eevee.taa_render_samples = samples
    for f in frames:
        path = os.path.join(out_dir, f"frame_{f:04d}.png")
        if os.path.exists(path):
            print("skip", f); continue
        sc.frame_set(f)
        sc.render.filepath = path
        bpy.ops.render.render(write_still=True)
```

## 随机种子：可复现的前提

```python
import random
SEED = 20261031
rng = random.Random(SEED)     # 用独立的 Random 实例，不要用全局 random
```

**用 `random.Random(SEED)` 而不是 `random.seed(SEED)`**——前者只影响这一个生成器，不会污染其他库的随机状态。

这样每次重跑脚本，生成的场景**完全一致**。这是"可复现"的基石。

## 本章要点回顾

- 集合是场景的文件夹，布尔切割工具要单独藏起来
- **链接 vs 复制**决定数据是否共享，实例化是省内存的关键
- 集合实例（Collection Instance）是批量复制"整栋房子"的最优解
- 命令行渲染用 `argparse` 做统一入口
- 序列渲染要支持**跳过已存在文件**，方便中断续渲
- **把生成脚本嵌进 .blend**，场景可追溯
- 用独立的 `random.Random(SEED)` 保证可复现
